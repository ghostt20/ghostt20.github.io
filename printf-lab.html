man variadic

Tap any yellow dotted word to see what it means. A {variadic} function (like printf) has {ellipsis} after its named parameters. It has no idea how many extra arguments came, or their types.

1. Where the caller puts arguments (Linux x86-64, {abi})

{rdi}{rsi}{rdx}{rcx}{r8}{r9}
1st2nd3rd4th5th6th

These are {register}s. Anything after the 6th integer or pointer goes on the {stack}, one 8-byte {slot} each. Floats use {xmm0} and friends. The caller also sets {rax}. In ft_printf, {rdi} holds the {fmt}.

2. va_start saves the registers into memory

Registers have no addresses, so {va_start} copies them into a block of memory and fills in a {struct}:

typedef struct {
  unsigned int gp_offset;      // next int arg in the saved block
  unsigned int fp_offset;      // next float arg
  void *overflow_arg_area;     // next arg that lives on the stack
  void *reg_save_area;         // the saved registers
} va_list[1];                  // 24 bytes

3. va_arg moves a bookmark

if (gp_offset < 48) { v = *(reg_save_area + gp_offset); gp_offset += 8; }
else                  { v = *overflow_arg_area; overflow_arg_area += 8; }

See it live in the Lab tab. The type you give {va_arg} decides how many bytes are read.

4. Rules that follow from this

  • {promotion}: read a char with va_arg(ap, int), never char.
  • Wrong type, or reading too many arguments, is {ub}.
  • Every {va_start} needs a {va_end}, also on early returns.
  • Pass va_list *ap to helpers so one real bookmark moves. Use {va_copy} to read twice.

5. Your ft_printf plan

  1. Loop over the {fmt}. Normal char: write it, count it.
  2. On %, read the next letter and call one small helper for that {conversion}.
  3. Add what each helper returns. If any returns -1, {va_end} and return -1.
  4. Return the total.
